# Список изменений

## 1.7.5

### Новые функции
- **Бейджи Jira-полей на странице коммитов** — показывает настраиваемые значения полей Jira (напр. Fix Version, статус, метки) в виде бейджей рядом с каждым коммитом на странице ветки. Название поля задаётся в настройках секции Jira (по умолчанию: fixVersions). Поддерживает несколько полей через запятую. Требуется URL Jira.

### Исправления
- **Модалка cherry-pick** — теперь показывает полное название коммита (корректная сборка текста при разбиении GitLab на несколько элементов) и позволяет перенос длинных строк.

## 1.7.1

### Исправления
- **Совместимость с GitLab 17.11** — исправлены сломанные селекторы после перехода GitLab на Vue-компоненты для списка MR и страниц коммитов. Кнопки cherry-pick, бейджи размера, индикаторы конфликтов, фильтры «Только мои» / «Нужна ревью» и бейджи Jira теперь работают на GitLab 17.11+.
- **Кроссверсионная поддержка** — все DOM-селекторы GitLab централизованы (объект `SEL`) с множественными фоллбэками: атрибуты `data-testid` (стабильное API GitLab) как основные, CSS-классы как запасные. Поддержка GitLab 16.x — 17.11+.
- **Надёжный поиск cherry-pick** — группы SHA коммитов теперь находятся двумя стратегиями: сначала CSS-селекторы, затем фоллбэк на кнопки буфера обмена с паттерном hex SHA. Работает даже при изменении всех имён классов.
- **Тайминг рендера Vue** — добавлен retry/polling для случаев, когда Vue ещё не отрендерил список MR или панель фильтров. Наблюдатель списка переключается на `document.body`, пока контейнер не появится.
- **Исправлена вставка бейджей** — исправлен краш `insertBefore`, когда ссылка заголовка вложена глубже внутри контейнера (новая DOM-структура GitLab).

## 1.7.0

### Новые функции
- **Cherry-pick в несколько веток** — cherry-pick любого коммита в несколько веток со страницы коммитов. Кнопка рядом с SHA каждого коммита. Модальное окно с выбором веток, статус в реальном времени (успех/конфликт). Возможность создать MR для каждого cherry-pick (как в нативном GitLab). Сохранение целевых веток по умолчанию в настройках.
- **Умный фоллбэк cherry-pick** — при ошибке из-за конфликтов в файле версии автоматически повторяет коммит через Commits API без файла версии, сохраняя оригинального автора. Опциональный бамп версии в целевой ветке. Оба варианта настраиваются.
- **Поиск файлов в командной палитре** — введите имя файла в Cmd+K для поиска файлов проекта и их открытия в репозитории.

## 1.6.0

### Новые функции
- **Командная палитра (Cmd+K)** — нажмите Cmd+K (Mac) или Ctrl+K (Win) на любой странице GitLab для вызова палитры с навигацией, действиями MR и командами расширения. Контекстная: действия MR на странице MR, навигация — на всех страницах.
- **Отчёт по дневной активности** — сводка вашей активности в GitLab за день (MR созданные, смёрженные, комментарии, аппрувы, в работе). Скопируйте и вставьте в Slack или Jira. Доступен через командную палитру или настройки расширения.

## 1.5.0

### Новые функции
- **Быстрый просмотр упавших джоб** — при падении пайплайна показывает имена упавших джоб и последние строки лога ошибки прямо на странице MR. Сворачиваемые блоки, первая джоба раскрыта. До 5 джоб с превью трейса.
- **Индикатор конфликтов** — красный бейдж CONFLICTS на странице MR и в списке при наличии конфликтов мёржа. Бейдж в списке настраивается.
- **Счётчик неразрешённых тредов** — красный бейдж в списке MR с количеством неразрешённых дискуссий. Данные через API, кэш 5 мин.
- **Размер MR** — цветные бейджи S/M/L/XL в списке MR по количеству изменённых строк (S: 1-50, M: 51-200, L: 201-500, XL: 500+). Фоллбэк на количество файлов для старых версий GitLab.
- **Быстрые комментарии** — настраиваемые шаблонные комментарии на странице MR. Отправка общего комментария одним кликом.
- **Сворачивание верхних панелей** — кнопка для сворачивания/разворачивания навигационных панелей GitLab. Состояние сохраняется в сессии.
- **Скрытие правой панели** — переключатель для скрытия правого сайдбара на страницах MR.
- **Версия из целевой ветки** — чтение текущей версии из целевой ветки (например, main) вместо исходной. Предотвращает устаревшие версии при стратегии merge commit.
- **Умная видимость кнопки Rebase** — кнопки rebase и rebase+version скрыты, когда метод мёржа проекта не требует ребейза (стратегия merge commit).

### Улучшения
- **Разделители мультитикетов Jira** — визуальные разделители между группами бейджей Jira при нескольких тикетах в заголовке MR.
- **Параллельная загрузка API** — метаданные MR (размер, треды, конфликты) загружаются пачками по 5 вместо последовательно.

## 1.4.0

### Новые функции
- **Сайдбар задачи Jira** — клик по бейджу Jira открывает сайдбар с полной информацией: тема, статус, резолюция, тип, приоритет, исполнитель, автор, метки, эпик, компоненты, версии, фикс-версии, даты и описание. Рендерит Jira wiki-разметку — изображения, видео, ссылки. Закрытие через × или Escape.
- **Вложения в сайдбаре** — просмотр изображений, видео и файлов, прикреплённых к задачам Jira. Изображения и видео открываются в лайтбоксе, файлы — в новой вкладке.
- **Бейджи Jira на странице MR** — бейджи статуса Jira в заголовке MR. Клик открывает сайдбар с подробностями.
- **Настраиваемый regex тикетов Jira** — регулярное выражение для парсинга ID тикетов из заголовков MR. Полезно при нестандартных префиксах.
- **Смена статуса Jira из сайдбара** — кнопки переходов под текущим статусом показывают только доступные переходы workflow. Смена статуса без выхода из GitLab.
- **Смена исполнителя Jira из сайдбара** — клик по имени исполнителя для поиска и назначения. Автокомплит с аватарами, поиск только среди назначаемых пользователей. Кнопка снятия назначения.
- **Быстрые действия Jira** — составные действия в настройках: смена статуса + назначение пользователя одним кликом. Кнопки появляются только при доступном переходе из текущего статуса.
- **Иконки типа и приоритета** — нативные иконки Jira для типа задачи и приоритета рядом с бейджами статуса в списке MR и на странице MR.
- **Спринт в сайдбаре** — отображение текущего спринта в сайдбаре задачи Jira.
- **Кликабельный Epic Link** — ссылка на эпик в сайдбаре открывает его в Jira в новой вкладке.

## 1.3.0

### Новые функции
- **Интеграция с Jira** — показывает статусы задач Jira цветными бейджами в списке MR. Парсит ID тикетов (например, `CCS-1111`) из заголовков MR и получает статус через Jira REST API с использованием сессионных cookies. Цветовая кодировка: зелёный (Done), синий (In Progress), фиолетовый (QA), жёлтый (In Review), серый (To Do). Скелетон-загрузчики при получении данных.
- **Копирование MR из списка** — кнопка копирования в панели управления каждого MR. Копирует заголовок + ссылку в буфер обмена одним кликом. Иконка зеленеет при успехе.
- **Фильтр «Нужна моя ревью»** — кнопка на странице списка MR для показа только MR, где вы назначены ревьюером. Работает через параметр `reviewer_username` GitLab.
- **Бейдж «Ваша ревью»** — сканирует первые 10 комментариев MR на паттерн «Reviewer(s): @вы» и показывает оранжевый бейдж. Для команд, назначающих ревьюеров через комментарии. Кэш 5 мин.

### Техническое
- Используется `chrome.cookies` API для авторизации Jira (сессионные cookies)
- Кэширование статусов (TTL 5 мин) для минимизации API-запросов
- Последовательная загрузка тикетов для снижения нагрузки на Jira
- Добавлены разрешения `cookies` и `optional_host_permissions` в манифест

- **Фильтр «Только мои»** — скрытие чужих MR в списке
