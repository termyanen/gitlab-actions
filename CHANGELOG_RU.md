# Список изменений

## Unreleased

- **Позиция списка при публикации ревью** — видимый комментарий и раскрытие карточек сохраняются при обновлении результатов, включая ошибки, увеличивающие высоту предыдущих карточек. Добавлены проверки массового раскрытия, смешанного состояния, прогресса и завершения в обеих темах и узком окне.

- **Развернуть или свернуть все комментарии** — в обоих окнах ревью добавлена общая кнопка над списком. Выбор действует только в текущем окне, сохраняется при обновлении карточек и не меняет настройки. Лишний боковой отступ убран, место для полосы прокрутки сохранено.

- **Компактные комментарии ревью** — длинные комментарии показывают пять строк с кнопками «Показать полностью» и «Свернуть», а колёсико прокручивает общий список. В настройках ревью можно включить полное отображение по умолчанию для всех проектов или отдельного проекта. Раскрытие сохраняется при публикации; добавлены переводы на все 27 языков.

- **Прокрутка ревью** — длинные комментарии для чтения прокручиваются вместе со списком и больше не перехватывают колёсико. В обеих колонках и редакторах заметнее полосы прокрутки; поля ввода сохраняют внутреннюю прокрутку и передают её колонке на границах.

- **Диагностика дневной активности** — ошибка формата ответа GitLab показывает источник, номер записи и поле без раскрытия значений ответа. Ошибка проверки не превращается в пустой отчёт.

- **Надёжность дневной активности** — допустимые пустые поля событий и MR GitLab больше не ломают весь отчёт; учитываются push-события и границы местных суток, включая переходы на летнее и зимнее время. Поздние правки MR не исключают старое слияние из запроса; лимиты отчёта и предупреждения сохранены.

- **Сворачиваемые блоки popup** — блок подключения Jira и пояснение области настроек можно свернуть независимо. Выбор сохраняется локально; большая страница настроек не меняется.

- **Прогресс отправки ревью** — во время отправки виден счётчик обработанных замечаний из выбранных. Для повтора остаются выбранными только подтверждённо неотправленные; публикации, черновики и неподтверждённые отправки исключены.

- **Результаты публикации ревью** — успешные замечания сохраняют высоту и прокрутку: зелёная рамка и статус без дополнительной строки. Итог отдельно показывает количество опубликованных замечаний, черновиков, неотправленных, ошибок и неподтверждённых отправок.

- **Выравнивание компактных настроек** — возврат к общему значению в попапе заменён доступной иконкой с переведённой подсказкой, чтобы не сжимать подписи кнопок. Удаление поля Jira выровнено рядом с селектом, пояснения отделены от кнопок отступом. На полной странице текстовые кнопки сохранены.

- **Единые размеры в маленьком окне** — попап и встроенные настройки используют текст элементов 14 px, согласованные отступы и высоты кнопок и полей, увеличенные области нажатия и компактные заголовки в обеих темах. Масштаб полной страницы сохранён.

- **Одно уведомление об обновлении** — встроенные настройки не создают повторный баннер новой версии; на отдельной странице уведомление сохраняется. Подсказка об автосохранении тоже остаётся только на полной странице; состояния сохранения, успеха и ошибок в попапе видны.

- **Прокрутка попапа** — разделы раскрываются на полную высоту под меню с одной общей прокруткой. Компактный блок подключения Jira перенесён наверх. Первое отображение ждёт локального ответа о доступе, чтобы карточка проекта не мигала над Jira и не сдвигалась вниз.

- **Настройки внутри попапа** — разделы открываются под меню в общем редакторе, без новой вкладки, с сохранением черновика и выбранного проекта. Кнопка полной страницы остаётся доступной.

- **Проектные настройки во всех разделах** — для проекта можно переопределять инструменты MR и коммитов, CI, Jira, AI-ревью и оформление GitLab. Видно, откуда взято значение; можно вернуть наследование общего. Прежние профили и общие значения сохраняются, а изменение одного поля больше не копирует в профиль остальные общие настройки. Поиск сохраняет выбранную область, popup использует адрес Jira проекта, экспорт/импорт включает переопределения. Язык, уведомления и параметры отчёта по всем проектам остаются общими. Новых разрешений в манифесте нет. При смене Jira-сервера проекта сбрасываются состояние авторизации и кэш задач; бейджи коммитов теперь читают текстовые файлы `VERSION`/`.text` и расширения JSON/TOML без учёта регистра.

- **Надёжность проектных настроек** — новые профили наследуют общие CI-задания до изменения списка. Открытые страницы настроек синхронизируют сохранённые изменения, профили и импорт; сохраняются только изменённые поля с учётом актуальных данных, поэтому посторонние изменения из другого окна не теряются. Неизменённые старые ветки и переопределения сохраняют исходный вид; импорт отклоняет записи без обязательных свойств. При выборе профиля игнорируются устаревшие метаданные SPA, cherry-pick на старых URL коммитов использует правильный профиль, кэш подробностей Jira разделён по серверам, а действия Jira на коммитах учитывают проектную настройку подтверждения.

- **Ветки cherry-pick для проекта** — задавайте целевые ветки в профиле проекта в разделе «MR и коммиты». Пустой список наследует общие ветки; настройки показывают итоговый список. Список коммитов и страница коммита используют соответствующий профиль, экспорт и импорт сохраняют переопределения. Подсказки доступны на всех 27 языках.

- **Обновление стилей расширения** — CSS получает имя по содержимому, и собранный манифест ссылается именно на этот файл. При изменении разметки панели новая сборка больше не использует прежний адрес CSS, в том числе при локальной пересборке без смены версии расширения. Браузерные проверки контролируют оформление установленного расширения под CSP страницы и замену старых стилей при обновлении распакованной копии.

- **Тема бейджей версий коммитов** — исправлен светлый фон в тёмной теме GitLab. Обычные бейджи и выделенные изменения версии учитывают тему на корневом элементе и родительском контейнере, используют семантические цвета GitLab при наличии и обновляются при переключении темы без перезагрузки.

- **Понятная панель MR** — действия и быстрые комментарии разделены на подписанные группы, время и предупреждения вынесены отдельно. У кнопок единые классы GitLab, размеры, цвета темы и клавиатурный фокус; длинные названия переносятся на узких страницах. Используется нативный средний размер, как у Merge: удалён конфликтующий класс маленьких кнопок, из-за которого стили GitLab сжимали их. Принудительное слияние и отмена пайплайна выделены цветом опасного действия. Единицы времени локализованы, некорректные даты больше не показывают NaN. Сохранены обновление настроек без перезагрузки, пользовательский порядок и состояние запущенных действий.

- **Настройки панели MR без перезагрузки** — сохранённые изменения видимости обычных и пользовательских кнопок, названий, порядка и быстрых комментариев сразу применяются на открытых страницах MR, включая профили и импорт. Неизменённые кнопки сохраняют фокус и состояние выполнения; устаревшие ответы настроек игнорируются, скрытые действия нельзя запустить из ранее открытой палитры команд. Обновление настроек не вызывает повторных запросов к GitLab.

- **Видимость пользовательских кнопок** — чекбоксы в списке кнопок теперь работают для собственных CI-заданий и MR-действий. Кнопки можно выключать без удаления настроек; состояние сохраняется после перезагрузки, перестановки, удаления соседних заданий, в профилях и при экспорте/импорте. Выключенные кнопки не показываются в панели MR и палитре команд. Существующие записи по умолчанию остаются включёнными.

- **Понятная навигация** — общий раздел настроек и popup переименован в **MR и коммиты** на всех 27 языках. Инструкции по настройке и снимок интерфейса на сайте обновлены.

- **Совместимость ответов GitLab MR** — допускается `should_remove_source_branch: null`, когда настройка удаления ветки не задана для MR. Строгая проверка раньше отклоняла весь ответ, и панель не появлялась. Принудительное удаление ветки по настройке проекта сохраняется; ошибки загрузки панели однократно выводятся в консоль вместо молчаливого пропуска.

- **Появление панели MR** — расширение дожидается ID проекта, если GitLab добавляет его после запуска, пропускает некорректные значения-заглушки и вставляет панель в актуальный контейнер после его замены во время запросов API. Повторные изменения страницы не дублируют кнопки; наблюдатель освобождается при навигации.

- **Проверка подключения к Jira** — настройки и popup подтверждают сессию браузера запросом текущего пользователя. Показываются время последней проверки, ссылка на вход при ошибке авторизации и отдельные ошибки доступа, сети и API. Проверка запускается по кнопке, не использует HTTP-кеш и не меняет данные Jira; смена адреса, отзыв доступа и закрытие страницы сбрасывают результат. Поддерживаются все 27 языков.

- **Доступ к Jira** — статус разрешения на доступ показывает домен Jira из настроек и больше не предлагает повторный вход авторизованным пользователям. В настройках и popup добавлена ссылка «Открыть Jira» по заданному HTTPS-адресу с сохранением пути установки; для неверного адреса ссылка не показывается. Исправлены все 27 переводов.
- **Навигация popup** — добавлены те же семь разделов и приветственная страница, что и в левой панели настроек; список пунктов общий. В быстрых настройках оставлены звук и системные уведомления. Тип и приоритет задач Jira настраиваются в разделе Jira. Переходы в разделы сохраняют контекст проекта.
- **Аккордеоны настроек** — вместо стандартных треугольников используются аккуратные шевроны в цветах темы; сохранены управление клавиатурой и режим уменьшенного движения.
- **Приветственная страница** — перенесена на общий React-дизайн: навигация по разделам, основной текст 16 px, светлая/тёмная темы и вёрстка для узких окон. Сохранены все инструкции и карточки на 27 языках. Страница использует выбранный в настройках язык и реагирует на его смену; при ошибке чтения настроек доступен повтор.
- **Настройки на React** — полная страница и компактный popup переведены на React + TypeScript с общими компонентами, типизированными черновиками и отдельной логикой сохранения. Сохранены дизайн в стиле GitLab, все настройки и профили, формат импорта/экспорта и 27 языков. React загружается только в окнах расширения, без добавления в скрипты GitLab и worker.
- **Состояние и восстановление настроек** — явный статус несохранённых изменений и ошибок с повтором; успешные уведомления о сохранении/импорте скрываются через 10 секунд; при ошибке загрузки редактирование недоступно, смена области ждёт подтверждения записи, а при закрытии с несохранёнными изменениями появляется предупреждение. Поиск находит глобальные настройки из профиля, пустые поля показывают наследуемые значения. Устранено повторное сохранение при потере фокуса, которое могло скрыть ошибку записи. Быстрые переключатели синхронизируются с открытой страницей настроек, чтобы редактирование других полей их не отменяло.
- **Новый интерфейс настроек** — компактный popup и полная страница с поиском, разделами и светлой/тёмной темой в стиле GitLab. «MR и коммиты» охватывает MR и страницы коммитов; лимиты находятся рядом со своими функциями. Явная область общих/проектных настроек, перестановка кнопок с клавиатуры и выровненные стрелки селектов сохраняют прежнюю конфигурацию и импорт/экспорт. Новые подписи переведены на все 27 языков; удаление быстрых комментариев, веток cherry-pick и кнопок jobs теперь сохраняется автоматически. Ссылка на приветственную страницу оформлена общим пунктом навигации в левой панели.

- **27 локализаций интерфейса** — к исходным семи добавлены 20 языков. Выбор языка интерфейса, ответов AI и импорт настроек используют общий каталог. Для каждой локали доступны все строки интерфейса и отдельное описание магазина; проверки охватывают весь каталог.

- **Восстановление доступа к Jira** — понятные ошибки входа, прав, сети и ответов API с повтором только чтения; доступные данные GitLab/Jira сохраняются. Отказ в доступе к одной задаче больше не отключает всю сессию Jira. Сохраняются неотправленный комментарий и результат частично выполненного действия; записи с неопределённым результатом не повторяются автоматически. Исправлено назначение исполнителя Server/Data Center, когда логин отличается от ключа пользователя; браузерная сессия используется без лишнего разрешения `cookies`. Отдельная кнопка в настройках выдаёт или восстанавливает доступ к сайту Jira; автосохранение не запрашивает разрешения.
- **Проверка внешних данных** — некорректные ответы GitLab/Jira и сообщения фонового процесса проверяются до использования; повреждённые состояния цепочек jobs не восстанавливаются. Ошибочные строки импорта ревью остаются доступными для исправления; сохранены частичный экспорт обсуждений и старые форматы с пустыми полями. Пути к версии в файле больше не обращаются к унаследованным свойствам объектов. Кнопки группового запуска jobs корректно обрабатывают исчезновение pipeline и сбрасывают прежнюю ошибку при успешной повторной попытке.
- **Точные описания функций** — исправлены README, сайт и onboarding: упоминания ревьюеров, фоновые цепочки jobs, подтверждения, выбор пайплайна и совместимость. Обновлены семь переводов интерфейса и скриншот настроек; убраны неподтверждённые обещания скорости и работы без настройки. Поведение расширения не изменено.
- **Настраиваемые правила отображения** — пороги размера MR, число упавших jobs и строк лога в предпросмотре, глубина поиска ревьюера, шаблоны чувствительных файлов и исключения. Прежние значения по умолчанию сохранены; настройки проверяются и входят в экспорт/импорт.
- **Точность предпросмотра** — бейдж ревьюера проверяет полное имя пользователя. Предпросмотр jobs ведёт к полному pipeline и не выдаёт частичный счётчик за итог. Неполные счётчики обсуждений и нижние границы числа файлов GitLab явно отмечаются.
- **Независимые предупреждения** — проверка чувствительных файлов работает при отключении всех кнопок и таймера; пустая панель больше не вызывает повторную инициализацию MR.
- **Прозрачные ограничения выборок** — проверка чувствительных файлов загружает следующие страницы diff и сообщает об ошибках API или достижении лимита. Standup предупреждает о возможной неполноте отчёта. Добавлен справочник настроек и ограничений, обновлены переводы настроек и описаний функций.

## 1.13.3

- **Поиск CI-джоб** — исправлен поиск для ревьюеров, пользовательских кнопок, фоновых цепочек и повтора упавших джоб: используется актуальный пайплайн MR и при необходимости проверяются следующие страницы джоб. Если встроенного пайплайна нет, сохраняется приоритет MR-пайплайнов GitLab для текущего коммита. Для форков учитывается проект джобы, в том числе в старых ответах без ID проекта пайплайна; повторный поиск после отказа retry остаётся в исходном пайплайне. Ошибка поиска содержит ID проверенного пайплайна.
- **Состояния очереди** — `preparing`, `waiting_for_resource` и `scheduled` считаются уже поставленными в очередь: без повторного play/retry и ошибки неизвестного статуса. Повторяющиеся страницы джоб останавливают поиск с переведённой ошибкой вместо бесконечного цикла.
- **Ожидание rebase** — при проверке явно запрашивается статус rebase. Отсутствие статуса или отказ в выполнении останавливают сценарий до изменения версии и мерджа, вместо того чтобы считаться успешным завершением.
- **Быстрые пайплайны** — Ship учитывает пайплайн, завершившийся между проверками, если SHA совпадает с текущей версией MR. Пайплайны прежних коммитов исключаются, когда доступен их SHA; сохраняется поддержка актуальных ссылок merged-results и merge-train пайплайнов MR.
- **Существующие обсуждения в новом ревью с ИИ** — необязательная галочка «Учесть существующие обсуждения» добавляет краткие сведения об опубликованных обсуждениях, чтобы помочь избежать повторных замечаний. Она выключена по умолчанию и запоминает выбор. Редактируемая автоматическая инструкция предлагает ИИ сначала самостоятельно проверить весь MR и затем убрать существенно повторяющиеся находки, включая уже решённые, без ответов и перепроверки существующих веток. Черновики, тексты ответов и обсуждения вне файловых фильтров не передаются; при ошибке загрузки показывается предупреждение. Выбор входит в экспорт и импорт настроек; при импорте старого файла опция остаётся выключенной.
- **Проверка обратной совместимости** — тестовые сценарии покрывают API-контракты GitLab от 12.10.14 до 18.11.0, включая старые поля пайплайнов, статус rebase и ответы о готовности к мерджу. Все 813 тестов проходят; 74 сценария прежнего поведения также проходят на исходном расширении 1.13.2. Это проверки исходных контрактов и моделируемых сценариев, а не сертификация на живых инсталляциях.

## 1.12.2

### Исправления
- **Повышение версии от целевой ветки сохраняет изменения исходной ветки** — из target читается только базовый номер версии; зависимости и остальные поля берутся из source. При записи передаётся последний коммит исходного файла, чтобы параллельное редактирование приводило к отказу, а не к перезаписи чужих изменений.
- **Цепочки CI-джоб остаются в исходном пайплайне** — пайплайн выбирается один раз для всей цепочки. Новый push или пайплайн больше не перенаправляет ожидание, повторные попытки и следующие джобы в другой пайплайн; повторно запущенные джобы внутри исходного пайплайна по-прежнему отслеживаются.
- **Отмена работающей цепочки останавливает следующие действия** — отмена во время поиска вкладок и джоб, запуска, повторного запуска или ожидания блокирует последующие запросы. Поздний ответ больше не заменяет отмену успехом или другой ошибкой. Явные запуски остаются независимыми, в том числе при появлении нового пайплайна того же MR; ID различаются даже при старте в одну миллисекунду.
- **Безопаснее fallback и повтор cherry-pick** — существующие ветки больше не удаляются при ошибке. Fallback останавливается при невозможности проверить файлы и защищает обновления/удаления от параллельных правок. Поддерживается явный ответ GitLab о конфликте и известный старый формат без кода ошибки, если удалось подтвердить реальные изменения других файлов; неоднозначная старая ошибка не создаёт коммит только с повышением версии. Повтор создания MR использует уже перенесённый коммит и проверяет, не был ли MR уже создан, без повторного повышения версии. Смена режима MR после ошибки учитывает выбранную ветку назначения.
- **Auto-merge различает постоянные ошибки и неготовность к слиянию** — ошибки авторизации, прав доступа и отсутствующего MR прекращают повторные запросы, даже если текст ответа не содержит код статуса. Для ответов GitLab 405, 406 и 422 сохраняется ограниченное число попыток; прежние параметры auto-merge оставлены для совместимости со старыми серверами.

- Релизные проверки следят за совпадением версии в manifest, метаданных сайта и обоих changelog. Тесты установки и обновления проверяют сохранение пользовательских настроек и уведомление о текущей версии.

Работа в настоящем браузере и автоматическое восстановление задач после перезапуска worker этим набором не покрываются.

## 1.12.1

### Исправления
- **Умный фолбэк cherry-pick: расхождение файла в другом месте больше не блокирует пик** — фолбэк требовал, чтобы каждый изменённый файл был байт-в-байт одинаковым в родителе коммита и в целевой ветке, поэтому отказывал там, где сам git мержит чисто (в целевой ветке были посторонние правки в другом месте того же файла). Теперь ханки диффа самого коммита строго переприменяются к содержимому целевой ветки: контекст каждого ханка обязан совпасть байт-в-байт ровно в одном месте, дифф сначала проверяется на родителе (обязан воспроизвести коммит в точности), а любое несовпадение, неоднозначность, бинарный файл или переименование по-прежнему приводят к отказу. Расширился только случай конфликта в файле версии — ничего не угадывается.
- **Умный фолбэк cherry-pick: коммиты только с версией** — коммит, менявший только файл версии, падал с ошибкой «No files left»; при включённом повышении версии теперь создаётся чистый bump-коммит.
- **Умный фолбэк cherry-pick: коммиты с 20+ файлами** — дифф коммита теперь запрашивается с пагинацией; раньше воспроизводились только первые 20 файлов, остальные молча терялись.

## 1.3.0

### Новые функции
- **Интеграция с Jira** — показывает статусы задач Jira цветными бейджами в списке MR. Парсит ID тикетов (например, `CCS-1111`) из заголовков MR и получает статус через Jira REST API с использованием сессионных cookies. Цветовая кодировка: зелёный (Done), синий (In Progress), фиолетовый (QA), жёлтый (In Review), серый (To Do). Скелетон-загрузчики при получении данных.
- **Копирование MR из списка** — кнопка копирования в панели управления каждого MR. Копирует заголовок + ссылку в буфер обмена одним кликом. Иконка зеленеет при успехе.
- **Фильтр «Нужна моя ревью»** — кнопка на странице списка MR для показа только MR, где вы назначены ревьюером. Работает через параметр `reviewer_username` GitLab.
- **Бейдж «Ваша ревью»** — сканирует первые 10 комментариев MR на паттерн «Reviewer(s): @вы» и показывает оранжевый бейдж. Для команд, назначающих ревьюеров через комментарии. Кэш 5 мин.

### Техническое
- Используется `chrome.cookies` API для авторизации Jira (сессионные cookies)
- Кэширование статусов (TTL 5 мин) для минимизации API-запросов
- Последовательная загрузка тикетов для снижения нагрузки на Jira
- Добавлены разрешения `cookies` и `optional_host_permissions` в манифест
