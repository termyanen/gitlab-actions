Язык: Японский (ja)

ワンクリックの自動化で、GitLabのマージリクエスト作業を効率化。rebase、バージョン更新、パイプライン管理、マージといった複数の手作業を、1つのボタンにまとめます。HTTPSのセルフホストGitLabとgitlab.comに対応します。利用できる機能はサーバーの機能とアカウントの権限に依存します。既存のブラウザーセッションを使うため、APIトークンは不要です。

★ お使いのツールでAIレビュー

• MR全体のレビュー — 設定可能なファイルフィルターを使い、MRの全コミットを対象としたタスクを作成
• 修正と返信 — 選択した指摘をコーディングAIにコピーし、投稿用の返信を準備
• 再レビュー — 選択したリビジョン以降の修正や変更を確認。force push後にも対応
• 編集可能なインポート — AIのコメントと返信をJSONで貼り付け、本文を編集して選択項目を投稿、またはレビューの下書きとして保存。返信の投稿後にディスカッションを解決済みにすることも可能
• カスタム指示 — プロンプトと自動追加の指示ブロックを編集し、回答言語を選択
• 手動で共有 — 好きなAIツールを利用可能。拡張機能にAIのAPIキーは不要で、コードの自動アップロードもありません

★ マージリクエストの操作

• 自動マージ — rebaseと「パイプライン成功後にマージ」の有効化をワンクリックで実行
• Ship — バージョン更新 → パイプライン → 自動マージというリリース作業を自動化
• 強制マージ — CIが不要な場合、パイプラインの完了を待たずにマージ
• バージョン更新 — package.json、pyproject.tomlなどのファイルでpatch / minor / majorを更新
• Rebase — バージョン更新の有無を選んでブランチをrebase
• 下書き / 準備完了 — タイトルを編集せずにMRの状態を切り替え
• クイックコメント — テンプレートのコメントをMRにワンクリックで投稿
• MRをコピー — タイトルとリンクをすぐにクリップボードへコピー

★ CI/CDパイプラインの操作

• 新規パイプライン / キャンセル — パイプラインをその場で作成または中止
• 失敗した全ジョブを再試行 — 最新パイプラインの失敗ジョブをまとめて再実行
• カスタムジョブボタン — 任意のCIジョブをワンクリックで実行。ビルド → デプロイなど、複数ジョブの連続実行にも対応
• エラーの簡易表示 — 失敗ジョブ名とエラーログの行をMRページで確認
• バックグラウンド実行 — ページを移動してもカスタムジョブの連続実行を継続

★ JIRA連携：APIトークン不要

• Jiraステータスバッジ — MRのタイトルから課題キーを抽出し、完了、進行中、QA、未着手などを色分けして表示
• 課題のサイドバー — バッジをクリックすると、件名、状態、担当者、優先度、スプリント、エピック、ラベル、説明、添付ファイルを表示
• 状態と担当者の変更 — GitLabを離れずに課題の状態を遷移させ、担当者を変更
• Jiraクイックアクション — 状態変更と担当者の設定などをワンクリックでまとめて実行
• 課題タイプと優先度のアイコン — MR一覧と詳細ページにJira標準のアイコンを表示
• コミット横のJira項目 — Fix Version、状態などの項目をコミットの横に表示
• 日次レポートへのJira情報追加 — 活動の要約に課題の件名を自動で追加

★ MR一覧の改善

• MRサイズ — 変更行数に応じたS / M / L / XLの色付きバッジ
• 競合の表示 — ブランチにマージ競合がある場合は赤いバッジを表示
• 未解決ディスカッション数 — 未解決の件数をひと目で確認
• ブランチ名 — 各MRにソース → ターゲットのブランチを表示
• 承認の表示 — 自分が各MRを承認済みかどうかを確認
• 下書きを薄く表示 — 作業中のMRに集中しやすい表示
• 自分のMRを強調 — 青い枠で簡単に識別
• 「自分のみ」「自分のレビュー待ち」「作成者でグループ化」の切り替え
• 「あなたのレビュー」バッジ — 設定したレビュアージョブとコメント内のメンションを検出
• 一覧からコピー — 各MRにコピーボタンを表示

★ 生産性向上ツール

• コマンドパレット（Cmd+K / Ctrl+K）— MR、パイプライン、ブランチ、課題への移動やアクションの実行
• ファイル検索 — パレットからプロジェクト内のファイルを名前で検索して開く
• 日次活動レポート — 作成、マージ、コメント、承認したMRを要約。SlackやJira向けにコピー可能
• 複数ブランチへのcherry-pick — コミットを複数ブランチに適用し、MRを自動作成
• Cherry-pickの再試行 — 競合時にはバージョンファイルを除外してコミットを自動で再適用
• 機密性の高いファイルの警告 — .env、Dockerfile、CI設定、認証情報のファイルをMRが変更する場合、オレンジ色のバッジを表示
• Gitコマンド — MRのブランチ用のgit checkoutとgit fetchをコピー
• MRの経過時間 — MRが開かれてからの時間を表示
• 自分のコメントを強調 — ディスカッション内の自分のコメントを色付きの枠で表示

★ カスタマイズ

• プロジェクト別プロファイル — リポジトリごとにボタン、バージョンファイル、CIジョブを設定
• ドラッグ＆ドロップで並べ替え — アクションボタンを好きな順番に配置
• 差分のタブ幅 — 2、4、8スペース相当の表示を選択
• 上部バーを折りたたむ / 右サイドバーを隠す — 作業スペースを拡大
• サウンドとデスクトップ通知 — アクションの完了や失敗を通知
• ダークテーマ — システムの設定に自動で追従

★ GITLAB MR ACTIONSを選ぶ理由

✓ 個人アクセストークン不要 — 既存のGitLabセッションのCookieを使用
✓ 仲介サービスなし — GitLabとJiraへのリクエストは設定済みサーバーへ直接送信
✓ HTTPSのセルフホストGitLabとgitlab.comに対応。検証済みのAPI契約は互換性ガイドを参照
✓ JiraもAPIトークン不要 — ブラウザーセッションを使用
✓ プロジェクトごとに柔軟に設定可能
✓ 軽量 — バックグラウンドの確認は自分で開始したアクションが対象。テレメトリやAIへの自動アップロードなし
✓ インターフェースは27言語に対応
✓ オープンソース

GitLabでのクリックを減らし、コードを書く時間を増やしたい開発者のために。
