ทำให้ workflow การ merge request ของ GitLab ของคุณง่ายขึ้นด้วยการคลิกครั้งเดียว แทนที่จะทำขั้นตอนหลายขั้นด้วยตนเอง — rebase, เพิ่มเวอร์ชัน, จัดการ pipeline, และ merge — ด้วยปุ่มเดียว รองรับ GitLab ส่วนตัว (HTTPS) และ gitlab.com; ขึ้นอยู่กับความสามารถของเซิร์ฟเวอร์และสิทธิ์ของบัญชี ไม่ต้องใช้ API token — ใช้ session ของเบราว์เซอร์ที่คุณมีอยู่

★ ตรวจสอบด้วย AI โดยใช้เครื่องมือของคุณเอง

• ตรวจสอบ MR ครบถ้วน — เตรียมงานที่ครอบคลุมทุก commit ของ MR พร้อมตัวกรองไฟล์ที่ปรับได้
• แก้ไขและตอบกลับ — คัดลอกความคิดเห็นที่เลือกไปยัง AI โค้ดของคุณและเตรียมคำตอบที่พร้อมโพสต์
• ตรวจสอบต่อ — ตรวจสอบการแก้ไขและการเปลี่ยนแปลงตั้งแต่ revision ที่เลือก รวมถึงหลังจาก force push
• นำเข้าแก้ไขได้ — วางความคิดเห็นและคำตอบของ AI เป็น JSON แก้ไขข้อความ และเผยแพร่รายการที่เลือกหรือบันทึกเป็นร่างการตรวจสอบได้ อีกทั้งสามารถปิดการสนทนาหลังจากเผยแพร่คำตอบ
• คำสั่งที่ปรับแต่งได้ — ปรับแต่ง prompt และบล็อกคำสั่งอัตโนมัติ เลือกภาษาที่ต้องการให้ตอบ
• แชร์ด้วยตนเอง — ใช้เครื่องมือ AI ที่คุณชอบ ไม่มีคีย์ API ของ AI ในส่วนขยาย และไม่มีการอัปโหลดโค้ดอัตโนมัติ

★ การดำเนินการ Merge Request

• Merge อัตโนมัติ — rebase และเปิดใช้งาน "merge when pipeline succeeds" เพียงคลิกเดียว
• ออกรุ่น — กระบวนการออกรุ่นเต็มรูปแบบ: อัปเดตเวอร์ชัน → pipeline → merge อัตโนมัติ ทั้งหมดเป็นอัตโนมัติ
• บังคับรวม — ข้าม pipeline และรวมทันทีเมื่อไม่ต้องใช้ CI
• เพิ่มเวอร์ชัน — เพิ่มเวอร์ชันใน package.json, pyproject.toml หรือไฟล์ใดก็ได้ (patch / minor / major)
• Rebase — ทำ rebase สาขา พร้อมหรือไม่พร้อมเพิ่มเวอร์ชันก็ได้
• สลับ Draft / Ready — เปลี่ยนสถานะ MR โดยไม่ต้องแก้ไขชื่อ
• ความคิดเห็นด่วน — โพสต์ความคิดเห็นตาม template ลง MR ได้แค่คลิกเดียว
• คัดลอก MR — คัดลอกชื่อ + ลิงก์ไปยัง clipboard ทันที

★ การควบคุม CI/CD PIPELINE

• Pipeline ใหม่ / ยกเลิก pipeline — สร้างหรือยกเลิก pipeline ได้ทันที
• ลองใหม่ทุก job ที่ล้มเหลว — รีสตาร์ททุก job ที่ล้มเหลวใน pipeline ล่าสุดพร้อมกัน
• ปุ่มงานแบบกำหนดเอง — เปิดใช้งานงาน CI ใดก็ได้ด้วยคลิกเดียว; ต่อหลาย job ด้วยกัน (เช่น build → deploy)
• ดูงานล้มเหลวแบบด่วน — เห็นชื่องานที่ล้มเหลวและบรรทัดบันทึกข้อผิดพลาดตรงบนหน้า MR
• การรันพื้นหลัง — สายงานแบบกำหนดเองยังดำเนินต่อหลังจากเปลี่ยนหน้า

★ การเชื่อมต่อกับ JIRA (ไม่ต้องใช้โทเค็น API)

• ตราสถานะ Jira — สถานะตั๋วที่มีสีต่างกัน (เสร็จแล้ว, กำลังทำ, QA, ต้องทำ) ที่ดึงมาจากชื่อ MR
• แถบข้างเต็มของตั๋ว — กดที่ตราใดก็ได้เพื่อดูสรุป, สถานะ, ผู้รับมอบหมาย, ลำดับความสำคัญ, สปรินต์, เอพิก, ป้ายกำกับ, คำอธิบาย และไฟล์แนบ
• เปลี่ยนสถานะ & ผู้รับมอบหมาย — ย้ายสถานะตั๋วและมอบหมายใหม่โดยไม่ต้องออกจาก GitLab
• การทำงานด่วนของ Jira — การกระทำรวม (เปลี่ยนสถานะ + มอบหมาย) แค่คลิกเดียว
• ไอคอนประเภทปัญหา & ลำดับความสำคัญ — ไอคอน Jira ดั้งเดิมบนหน้ารายการ MR และหน้ารายละเอียด
• แท็กฟิลด์ Jira บนคอมมิต — แสดง Fix Version, สถานะ หรือฟิลด์อื่น ๆ ข้างคอมมิต
• การเสริม Jira ในรายงานประจำวัน — ชื่อประเด็นถูกเพิ่มอัตโนมัติในสรุปกิจกรรม

★ การปรับปรุงรายการ MR

• ป้ายขนาด MR — ป้าย S / M / L / XL มีสีต่างกันตามจำนวนบรรทัดที่เปลี่ยน
• ตัวบ่งชี้ความขัดแย้ง — ป้ายสีแดงเมื่อสาขามีความขัดแย้งในการรวม
• จำนวนกระทู้ที่ยังไม่แก้ไข — ดูกระทู้ที่เปิดคุยได้ทันที
• ชื่อสาขา — แสดงสาขาต้นทาง → สาขาปลายทางในแต่ละ MR
• ตัวบ่งชี้การอนุมัติ — แสดงว่าคุณอนุมัติ MR แต่ละอันหรือไม่
• ทำให้ MR แบบร่างจางลง — มองเห็น MR ร่างแบบจาง ๆ เพื่อโฟกัสบน MR ที่ใช้งาน
• ไฮไลต์ MR ของคุณ — ขอบสีน้ำเงินบน MR ของคุณเพื่อให้หาง่าย
• สลับ "เฉพาะของฉัน" / "ต้องการให้ฉันตรวจสอบ" / "จัดกลุ่มตามผู้เขียน"
• เหรียญ 'รีวิวของคุณ' — ตรวจจับการกล่าวถึง reviewer-job ที่ตั้งค่าไว้ และการกล่าวถึงในคอมเมนต์
• คัดลอก MR จากรายการ — ปุ่มคัดลอกบนแต่ละรายการ MR

★ เครื่องมือเพิ่มประสิทธิภาพ

• แผงคำสั่ง (Cmd+K / Ctrl+K) — ไปยังรายการ MR, pipeline, สาขา, ปัญหา หรือเรียกใช้งานคำสั่งต่างๆ
• การค้นหาไฟล์ในแผง — หาชื่อไฟล์โปรเจกต์แล้วเปิดได้เลย
• รายงานกิจกรรมประจำวัน — สรุป MRs ที่สร้าง, รวม, คอมเมนต์, หรืออนุมัติ คัดลอกไป Slack หรือ Jira
• Cherry-pick ไปหลายสาขา — cherry-pick commit ใดก็ได้ไปหลายสาขาพร้อมสร้าง MR อัตโนมัติ
• วิธีสำรองอัจฉริยะสำหรับ cherry-pick — เล่น commit ซ้ำโดยยกเว้นไฟล์เวอร์ชันถ้าเกิด conflict
• แจ้งเตือนไฟล์สำคัญ — แสดงเหรียญสีส้มเมื่อ MR มีการแก้ไข .env, Dockerfile, การตั้งค่า CI หรือข้อมูล credential
• ปุ่มคำสั่ง Git — คัดลอกคำสั่ง git checkout และ git fetch สำหรับสาขา MR
• ป้ายอายุ MR — ดูว่า merge request เปิดมานานเท่าไร
• ไฮไลต์คอมเมนต์ของฉัน — ขอบสีรอบคอมเมนต์ของคุณเองในบทสนทนา

★ การปรับแต่ง

• โปรไฟล์ต่อโปรเจกต์ — ปุ่ม, ไฟล์เวอร์ชัน และงาน CI ที่แตกต่างกันสำหรับแต่ละ repository
• ลากแล้ววางลำดับปุ่ม — จัดเรียงปุ่มการกระทำตามที่คุณชอบ
• ตั้งค่าความกว้างแท็บใน diff — ตั้งค่าแสดงแท็บเป็น 2, 4 หรือ 8 ช่องว่าง
• ย่อแถบด้านบน / ซ่อนแถบด้านขวา — เพิ่มพื้นที่ทำงานให้มากที่สุด
• การแจ้งเตือนเสียง & บนเดสก์ท็อป — รับการแจ้งเตือนเมื่อการทำงานเสร็จสมบูรณ์หรือล้มเหลว
• ธีมมืด — ปรับตามการตั้งค่าระบบโดยอัตโนมัติ

★ ทำไมต้องใช้ GitLab MR Actions?

✓ ไม่ต้องใช้ personal access tokens — ใช้คุกกี้เซสชัน GitLab ที่คุณมีอยู่แล้ว
✓ ไม่มีบริการตัวกลาง — คำขอ GitLab และ Jira ส่งตรงไปยังเซิร์ฟเวอร์ที่คุณตั้งค่าไว้
✓ รองรับ GitLab แบบ self-hosted ผ่าน HTTPS และ gitlab.com; ดูคู่มือความเข้ากันได้สำหรับ API ที่ทดสอบแล้ว
✓ การรวม Jira โดยไม่ต้องใช้ API tokens — ใช้คุกกี้เซสชันเบราว์เซอร์
✓ ปรับแต่งได้เต็มที่ต่อโปรเจกต์ — ไม่มีข้อจำกัดแบบเดียวสำหรับทุกโครงการ
✓ น้ำหนักเบา — การตรวจสอบเบื้องหลังทำงานตามการกระทำที่คุณเริ่ม; ไม่มีการส่งข้อมูล telemetry หรืออัปโหลด AI อัตโนมัติ
✓ รองรับภาษาของอินเทอร์เฟซ 27 ภาษา
✓ โอเพนซอร์ส
