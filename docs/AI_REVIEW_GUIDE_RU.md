# Ревью MR с ИИ

Мини-гайд для ревьюера, автора MR и коллег, которые подключаются к проверке позже. Обычный цикл: **ревью → публикация замечаний → исправления → ответы → повторная проверка**. Один MR могут проверять несколько человек, каждый со своим ИИ.

Расширение готовит текст для ИИ и размещает выбранные результаты в GitLab. Сам ИИ запускается отдельно: вы вставляете ему скопированное задание, а его ответ возвращаете в расширение. Комментарии публикуются от вашей текущей учётной записи GitLab с её правами.

## Какой сценарий выбрать

Откройте **«Ревью с ИИ…»** и выберите вкладку. Во всех вкладках основная кнопка одна — **«Скопировать задание»**.

| Вкладка | Когда нужна | Что выбрать |
|---|---|---|
| **Новое ревью** | Первое или независимое ревью всего MR | Описание, включение кода и при необходимости фильтры файлов |
| **Исправить замечания** | Нужно внести исправления в код | Замечания для вашего ИИ; изначально выбраны нерешённые |
| **Подготовить ответы** | Исправления отправлены, нужны ответы ревьюеру | Опубликованные обсуждения, на которые хотите ответить |
| **Повторное ревью** | Нужно проверить исправления и новые изменения | Обсуждения и ранее проверенную версию; без версии проверяется текущий MR целиком |

Подсказка под вкладкой объясняет задачу, а сводка показывает, что войдёт в текст. **«Дополнительные настройки»** содержат инструкции для выбранной задачи, а для нового и повторного ревью — фильтры файлов. **«Предпросмотр»** готовит текст без копирования. **«Вставить ответ ИИ»** открывает проверку результата перед публикацией.

Задачу определяет вкладка. Снятие всех галочек **не переключает на новое ревью**: во вкладках «Исправить замечания» и «Подготовить ответы» копирование станет недоступно, а «Повторное ревью» проверит только код. Переключение вкладок сохраняет выбор обсуждений и отдельные правки промптов, но сбрасывает подготовленный текст.

Для ответов и повторной проверки выбор хотя бы одного комментария включает всю его ветку. Сводка считает обсуждения; во вкладке «Исправить замечания» показано число выбранных комментариев. Чтобы исключить ветку, снимите все её галочки.

Для всех обсуждений, включая решённые и общие, нажмите **«Выбрать все обсуждения»**. Галочки в импорте отдельно определяют, что публиковать.

По умолчанию окна ревью закрываются без подтверждения. В настройках расширения, в разделе «Ревью с ИИ», можно включить **«Подтверждать закрытие окон ревью с несохранёнными изменениями»**. Тогда при изменённых полях, выборе комментариев или незавершённом импорте появится вопрос; отмена закрытия сохранит работу. Полностью завершённый импорт закрывается без вопроса даже при включённой настройке. Закрытие во время отправки останавливает дальнейшую отправку, но не отменяет уже отправленные комментарии.

## Перед началом

Откройте MR. Наведите курсор на иконки расширения: подсказки покажут **«Ревью с ИИ…»** и **«Импортировать ревью ИИ…»**. Если кнопок нет, проверьте включение функции в настройках расширения; после обновления расширения обновите страницу GitLab.

- **Сначала локальный репозиторий.** По умолчанию экспорт компактный. Открывайте задание в ИИ, которому доступен проект на компьютере. Промпты предписывают сначала проверить локальный Git, а недостающие коммиты получить через проверенный настроенный remote с существующей авторизацией. Для ревью ИИ проверяет указанные версии без переключения вашей ветки, при необходимости в отдельном worktree. При исправлении сохраняет более поздние коммиты и незакоммиченные правки в ветке MR. Правила применяются и к сохранённым пользовательским промптам — сбрасывать их не нужно. Если локальный код недоступен, включите **«Включить изменения кода»** для нового или повторного ревью. Diff может не содержать зависимостей и тестов: ИИ должен запросить конкретные недостающие данные, а не доступ к GitLab по умолчанию.
- **Описание MR.** **«Добавить описание»** включает требования и пояснения автора. Выбор запоминается. Галочка **«Включить изменения кода»** при новом открытии выключена.
- **Область проверки.** В **«Дополнительные настройки» → «Файлы для ревью»** можно задать пути и исключения для текущего копирования. Пустые списки включают всё. Например, `src/**` в путях ограничит проверку этой папкой. Расширения и пути включения работают как альтернативы, исключения имеют приоритет. Проверка части файлов не означает проверку всего MR.
- **Язык и стиль.** В настройках **«Ревью с ИИ»** есть отдельные промпты для исправлений, ревью с нуля, новых замечаний, ответов и повторного ревью. В поле **«Язык ответа ИИ»** выберите русский или другой язык для всех заданий и промптов импорта. Автоматический режим ориентируется на язык диалога с ИИ. Настройка не зависит от языка интерфейса и имеет приоритет над языковыми указаниями в сохранённых промптах. Имена полей JSON, пути и код не переводятся; копирование только формата не добавляет указание языка. Критерии и стиль задавайте в промптах. Адрес MR, версии и формат результата расширение добавляет само.

## Настройка автоматических инструкций

Откройте **«Ревью с ИИ → Автоматические инструкции (дополнительно)»** в настройках расширения. Все 31 блока изначально включены и применяются к соответствующим задачам. Раскройте блок, чтобы изменить текст, отключить его с сохранением текста или очистить текст для исключения из задания. Сброс восстанавливает английский текст по умолчанию и включает блок. Лимит каждого текста — 1500 символов. `{language}` подставляет выбранный язык ответа, `{selection}` — выбранные или нерешённые обсуждения для ответа.

Основные промпты задач редактируются отдельно и тоже могут содержать похожие инструкции. Итоговое сочетание видно в полном предпросмотре задания. Идентификаторы MR, JSON-примеры и сообщения о загрузке формируются из текущего контекста; изменение инструкций не отключает фильтры файлов, проверку привязок и проверки перед публикацией. Кнопка копирования только формата всегда выдаёт поддерживаемый формат импорта без инструкций задачи.

## Ревьюер проверяет MR с нуля

1. Откройте **«Ревью с ИИ…»** и выберите вкладку **«Новое ревью»**.
2. Настройте файлы, описание и включение кода. При необходимости измените промпт для этого копирования.
3. Нажмите **«Предпросмотр»**, затем **«Скопировать задание»**. Можно сразу скопировать без предпросмотра.
4. Вставьте задание ИИ с доступом к нужной версии репозитория. Он должен проверить совокупный результат всех коммитов, прочитать необходимый контекст и вернуть JSON с замечаниями. В этом сценарии код не исправляется.
5. Проверьте результат и опубликуйте нужное по инструкции ниже.

Выбор обсуждений не влияет на вкладку «Новое ревью»: она всегда проверяет весь MR в заданной области файлов.

В дополнительных настройках окна импорта остаётся короткий путь: **«Копировать промпт для нового ревью»**. Он не прикладывает описание и diff. Обычный путь с этими опциями — вкладка «Новое ревью».

Если задача и контекст кода уже переданы ИИ, нажмите **«Копировать формат ответа»** рядом с кнопками промптов в импорте. Скопируются только структура JSON и правила полей для замечаний к строкам, общих комментариев и ответов — без настроенных промптов и загрузки данных MR. ИИ должен заполнить примеры из проверенного контекста: для новых замечаний указать реально проверенную версию кода, а для ответов — настоящие ID обсуждений и комментариев. В JSON только с ответами `head_sha` можно не указывать.

## Проверка и публикация результата ИИ

Эти шаги одинаковы для новых замечаний, ответов и повторного ревью.

1. Нажмите **«Вставить ответ ИИ»** в окне ревью или отдельную иконку **«Импортировать ревью ИИ…»**.
2. Вставьте весь JSON в **«Ответ ИИ (JSON)»** и нажмите **«Проверить и посмотреть»**. Импорт сверит MR, версию и места в коде для новых замечаний, а для ответов — нужные обсуждения. Эта проверка подтверждает адресацию комментариев, а не правильность выводов ИИ.
3. Прочитайте карточки. Снимите галочки с лишних замечаний и смысловых повторов. У ответов проверьте исходное обсуждение.
4. Иконкой **«Редактировать текст»** измените или дополните формулировку, затем нажмите **«Сохранить изменения»**. Место в файле и обсуждение остаются прежними. **«Добавить комментарий»** создаёт ваш общий комментарий к MR.
5. Выберите **«Опубликовать выбранные»** для немедленной отправки либо **«Добавить в ревью»** для сохранения в свои черновики GitLab. Черновики затем нужно отправить штатной кнопкой завершения ревью в GitLab, чтобы коллеги их увидели.
6. Посмотрите результат у каждой карточки: часть комментариев может отправиться, а часть потребовать исправления или повторной проверки.

Предпросмотр и сохранение правок ничего не публикуют. У ответа на открытое обсуждение, которое можно решить, есть галочка **«Закрыть обсуждение после публикации»** — по умолчанию выключена. Расширение сначала публикует ответ, повторно проверяет ветку и затем запрашивает закрытие с вашими правами GitLab. Результат закрытия отображается отдельно. Если закрытие не удалось или не подтверждено, ответ остаётся опубликованным: проверьте ветку в GitLab, не отправляя ответ повторно. Добавление черновика не закрывает обсуждение; галочка также не откладывает закрытие до публикации черновика. Approve, повторное открытие обсуждения и merge выполняются отдельно в GitLab по процессу команды.

Если ИИ не нашёл проблем и вернул пустой список, публиковать нечего. Само отсутствие замечаний не создаёт одобрение MR.

## Автор MR или коллега исправляет замечания

1. Откройте **«Ревью с ИИ…» → «Исправить замечания»**, нажмите **«Обновить»**, если обсуждения изменились.
2. Нажмите быструю кнопку **«Нерешённые»**: она выбирает все нерешённые обсуждения. Снимите галочки с задач, которыми занимается другой человек. Общие комментарии включайте отдельно галочкой **«Общие комментарии»**.
3. Нажмите **«Скопировать задание»** и передайте задание ИИ, работающему с кодом ветки MR. Здесь используется промпт для исправлений. Остальные ответы в выбранных ветках передаются как контекст.
4. Проверьте изменения и выполните необходимые проверки. Если замечание спорное, уже исправлено или непонятно, разберите его вместо формального изменения кода.
5. Сохраните исправления в коммитах и отправьте их в ветку MR своим обычным способом. Расширение копирования и импорта этого не делает.
6. С включённой галочкой **«Сразу подготовить ответы»** задание на исправление также возвращает JSON с ответами в выбранные опубликованные обсуждения MR: что сделано, что осталось и почему что-то не менялось. После отправки всех коммитов нажмите **«Вставить ответ ИИ»**, проверьте и отредактируйте ответы, выберите нужные и опубликуйте. Повторный запрос к ИИ или обновление SHA не нужны. В JSON только с ответами `head_sha` можно не указывать; прежний SHA не блокирует ответы. Новые замечания по-прежнему требуют проверенной версии.

**«Подготовить ответы»** остаётся полезным, если код исправлен вручную или нужны новые формулировки. Ответы на неопубликованные черновики без опубликованной ветки импортировать нельзя.

Галочка **«Сразу подготовить ответы»** во вкладке **«Исправить замечания»** включена по умолчанию. Снимите её, если нужны только исправления и обычный отчёт без ответов для импорта. Выбор действует в открытом окне и сохраняется при переключении вкладок.


Для одного замечания используйте иконку рядом с ним. Если в ветке есть ответы, внутри окна нажмите **«Выбрать это обсуждение»**, затем **«Скопировать задание»**. Короткие фрагменты кода у замечаний сохраняются независимо от галочки включения diff.

При смене фильтра статуса прежнее выделение сбрасывается. Перед копированием проверьте выбранные пункты; **«Выбрать все обсуждения»** используйте, когда действительно нужен весь набор обсуждений.

## Ответить что исправлено и как

1. Убедитесь, что исправления уже отправлены в MR. Обновите страницу.
2. Откройте **«Ревью с ИИ…» → «Подготовить ответы»**, выберите нужные обсуждения и нажмите **«Скопировать задание»**. Для ответов на все открытые замечания сначала нажмите **«Нерешённые»**.
3. Передайте промпт ИИ с доступом к опубликованной версии кода. Он должен сопоставить замечания с кодом и подготовить конкретные ответы: что изменено, где, какие проверки действительно выполнены и что осталось.
4. Импортируйте JSON через **«Проверить и посмотреть»**. Оставьте только ответы, которые хотите отправить от своего имени, отредактируйте текст и опубликуйте.

**В окне копирования ответы готовятся только для выбранных опубликованных обсуждений.** Можно выбрать и решённую или общую ветку, если GitLab позволяет адресовать в неё ответ. Файловые фильтры не исключают выбранные ветки. Без выбора кнопка недоступна; черновики не являются адресатами таких ответов.

В окне импорта нет выбора исходных обсуждений. Там в дополнительных настройках кнопка **«Промпт ответов на все нерешённые»** берёт все открытые ветки, без общих и решённых. Если нужна часть обсуждений, готовьте задание из окна копирования. В обоих случаях окончательный набор отправляемых ответов выбирается в предпросмотре импорта.

Ответ «сделано» должен подтверждаться опубликованным кодом. Нельзя описывать только локальные, ещё не отправленные изменения как уже доступные ревьюеру. Если исправлено частично, нужен вопрос или замечание неприменимо, ответ должен прямо это объяснять.

## Ревьюер проверяет исправления повторно

Ответ повторного ревью должен быть коротким: обычно 1–3 предложения с результатом проверки и одним подтверждающим фактом или оставшейся проблемой. Не нужно пересказывать исходное замечание, повторять ответ автора, перечислять посторонние тесты или добавлять итог всего MR в каждую ветку. Новые проблемы оформляются отдельными замечаниями.

1. Откройте **«Ревью с ИИ…» → «Повторное ревью»** и выберите обсуждения для проверки. Для решённых веток переключите фильтр; для всех — выберите **«Все»**, очистите поиск и нажмите **«Выбрать показанные»**.
2. В **«Версия, которую вы проверяли»** выберите состояние MR, на котором делали предыдущую проверку. Можно выбрать **«Указать SHA коммита»** и вставить полный SHA. Если версия неизвестна, оставьте **«Полная проверка — без прежней версии»**.
3. Задайте область проверки и при необходимости включите код. Нажмите **«Скопировать задание»** и передайте скопированное задание ИИ.
4. ИИ проверяет выбранные прежние замечания, ответы и текущий код, затем ищет новые проблемы в рамках файловых фильтров. В результате могут быть и ответы в старые ветки, и новые замечания.
5. Импортируйте результат, уберите ненужные ответы и повторы, проверьте формулировки и опубликуйте выбранное.

**Если после замечаний было 10 коммитов**, выберите версию, которую проверяли до этих исправлений. Все изменения от неё до текущего состояния входят в задачу автоматически; выбирать каждый коммит не нужно.

После rebase или force push выбирайте тот же ранее проверенный SHA. Сравниваются состояния кода, поэтому прежний коммит не обязан оставаться предком нового. Если он недоступен, нужна полная проверка текущего MR с прежними замечаниями; это не подтверждение проверки точной разницы версий.

При включённом коде копируется разница выбранной и текущей версии без дублирования полного diff. Если сравнение недоступно, прикладывается текущий diff с предупреждением. Без прежней версии или при совпадающем SHA прикладывается полный текущий diff: могла измениться целевая ветка.

**Повторное ревью проверяет только выбранные обсуждения и отдельно ищет новые проблемы в коде.** Выбор веток не ограничивает проверку кода файлами из этих веток: её область задают файловые фильтры. Замечание вне выбранной области нельзя объявлять исправленным без проверки. Статус «решено» и ответ «исправлено» сами по себе не доказывают исправление.

Во вкладке **«Повторное ревью» без выбранных обсуждений** ИИ получает задачу только на код: без проверки прежних замечаний и ответов на них. Это отличается от вкладки **«Новое ревью»**, которая проверяет весь текущий MR в выбранной области без привязки к прежнему ревью.

## Несколько ревьюеров и несколько исполнителей

У каждого участника свои ИИ, настройки и выбранная версия сравнения. Общий контекст — опубликованный код и обсуждения GitLab. Расширение не хранит историю проверок и не назначает замечания участникам.

| Ситуация | Как действовать |
|---|---|
| Два человека делают независимое ревью | Каждый запускает «Новое ревью». Перед публикацией оба смотрят существующие обсуждения и убирают повторы |
| Нужно учесть уже проведённое чужое ревью | Выберите нужные ветки или все обсуждения, затем запустите «Повторное ревью» с полной проверкой без прежней версии |
| Ревью делят по областям | Договоритесь, кто проверяет какие файлы, и задайте соответствующие фильтры. Отдельно определите, кто проверит взаимодействие частей |
| Два человека исправляют замечания | Каждый копирует только свои выбранные замечания. Согласуйте работу с общей веткой, чтобы изменения не перекрывали друг друга |
| Каждый хочет отвечать только за свои исправления | В окне копирования каждый выбирает свои ветки во вкладке «Подготовить ответы» и нажимает «Скопировать задание», затем проверяет ответы перед публикацией |
| Один проверял версию A, другой версию B | При повторном ревью каждый выбирает свою проверенную версию. Не используйте автоматически последнюю версию из списка |
| Коллега уже ответил, пока ИИ готовил результат | Перечитайте обновлённую ветку. Если импорт сообщает об изменении обсуждения, получите свежий контекст и проверьте ответ заново |

Расширение распознаёт совпадающие комментарии, но не гарантирует обнаружение одинаковых по смыслу замечаний с разным текстом или одновременных публикаций разных участников. Ненужные дубли убираются в предпросмотре. Чужие неопубликованные черновики не следует считать общим контекстом команды.

Чтобы позже выбрать правильную версию, можно оставить проверенный SHA в своём итоговом комментарии к ревью или сохранить исходное задание в чате с ИИ. Отдельная запись истории в расширении для этого не создаётся.

## Если что-то изменилось или не загрузилось

| Что произошло | Что делать |
|---|---|
| Удалили опубликованный ответ или замечание и хотите отправить тот же текст | Нажмите «Проверить и посмотреть» заново. Импорт проверит сохранённый ID комментария в GitLab и снимет блокировку, если он отсутствует. Добавлять пробелы или менять текст не нужно |
| Удалили добавленный черновик и хотите добавить снова | Нажмите «Проверить и посмотреть» заново. После подтверждения отсутствия черновика в GitLab его можно выбрать снова. При недоступном списке черновиков или неизвестном результате отправки защита от дублей сохраняется |
| Пока ИИ работал, в MR появились новые коммиты | Готовые ответы можно импортировать после отправки исправлений; проверьте их текст. Новые замечания требуют перепроверки. Не подменяйте SHA в старом JSON ради публикации |
| Комментарий привязан к неверной строке | Передайте ИИ сообщение проверки и актуальный diff, получите исправленный результат. Редактор предпросмотра меняет текст, а не привязку |
| GitLab не вернул полный diff файла | Импорт автоматически пытается догрузить отсутствующие или обрезанные изменения из Git-хранилища GitLab через вашу текущую сессию. Размер ответа ограничен 16 МиБ; точный текст строки и версия MR по-прежнему проверяются. Если сервер не вернул проверяемый diff, этот комментарий остаётся заблокированным, а остальные готовые можно отправить. После временной ошибки повторите «Проверить и посмотреть» либо подготовьте общий комментарий MR, указав файл и строку в тексте |
| Отправка не подтверждена | Сначала проверьте обсуждение в GitLab. Комментарий мог сохраниться; повторная отправка вслепую создаст дубль |
| Выбранная ветка исчезла или недоступна | Обновите обсуждения и проверьте выбор. Подготовка ответов остановится; повторное ревью отметит недостающую ветку предупреждением и не должно считать её проверенной |
| Загрузилась только часть данных | Прочитайте предупреждение, попробуйте обновить данные или передайте недостающий код ИИ отдельно. Неполный контекст не даёт основания считать весь MR проверенным |
| Нет доступа к коду у ИИ | Включите изменения кода для ревью и передайте необходимые дополнительные файлы. Одна ссылка на приватный MR не даёт ИИ доступа |
| Нет списка версий на старом GitLab | Введите полный SHA вручную либо выберите полную проверку |
| Не работает «Добавить в ревью» на сервере | Проверьте сообщение об ошибке. Автоматической замены на публичную отправку нет; непосредственную публикацию выбирайте отдельно |
| Комментарий создан через GitLab Add to review | Это черновик. Его можно скопировать отдельной иконкой, но коллеги увидят его после публикации ревью |
| Буфер обмена недоступен | Скопируйте подготовленный текст из предпросмотра вручную |

Для issue доступны копирование замечаний и описание для работы с ИИ. Ревью кода с нуля, повторное ревью версий и импорт комментариев из этого гайда относятся к MR.
